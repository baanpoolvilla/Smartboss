# สรุปงาน: ระบบไฟล์ สิทธิ์ และเพดานความจุ

วันที่: 1 ก.ย. 2026
ขอบเขต: `apps/web` (โมดูล report_task, company-files, maintenance, admin) + schema ฐานข้อมูล
สถานะ: แก้โค้ดครบแล้ว **ยังไม่ deploy** — ทั้งหมดแก้โค้ดล้วน ไม่แตะข้อมูลเดิม

---

## 1. แก้ popup "มีคนแก้พร้อมกัน" + ให้หลายคนแก้พร้อมกันได้

**อาการเดิม:** ข้อความ "มีคนอื่นแก้ไขข้อมูลพร้อมกัน กำลังโหลดข้อมูลล่าสุด" เด้งบ่อยมาก
ทั้งที่ไม่มีใครแก้ของชิ้นเดียวกัน

**ต้นตอ:** ทั้งฟีดขององค์กร (topics + posts ทุกช่อง) ถูกเก็บเป็นก้อนเดียวใน DB คุมด้วยเลข
version เดียว ใครเซฟที่ไหนก็ทำ version ทั้งก้อนขยับ เครื่องอื่นที่ถือเลขเก่าจึงชน 409
เป็นประจำ (optimistic concurrency ที่หยาบเกินไป) — ไม่ใช่การแก้ชนกันจริง

**แก้ยังไง:** เปลี่ยนจาก "เจอชน → เด้ง popup → โหลดทับ (งานที่พิมพ์หาย)" เป็น
**merge อัตโนมัติ**: ดึงของล่าสุด → รวมงานเราทับตาม id ของแต่ละโพสต์/หัวข้อ → เซฟใหม่เงียบ ๆ
คนละชิ้นไม่ชนกัน + เพิ่ม auto-refresh เบา ๆ ทุก 4 วิ ให้เห็นงานคนอื่นเองโดยไม่ต้องรีเฟรช

**ไฟล์:**
- ใหม่ `modules/report_task/components/shared/store-merge.ts` — 3-way merge (ทดสอบผ่าน 7/7 เคส)
- แก้ `modules/report_task/components/shared/server-store-sync.tsx` — merge+retry, poll 4 วิ, กัน loop เขียนวน

**หมายเหตุ:** โมดูล "งาน/tasks" ใช้ตัว sync แยก (`task-sync.tsx`) ที่ยังเด้ง toast แบบเดิม — ทำเพิ่มได้ถ้าต้องการ

## 2. อุดช่องโหว่ไฟล์ข้ามบริษัท (multi-tenant)

**ปัญหา:** route เสิร์ฟไฟล์ `/api/files/[...key]` เดิมเช็คแค่ "login อยู่ไหม" — ใครได้ URL ไฟล์
(หลุด/แชร์ผิด) ก็โหลดข้ามบริษัทได้ และคนในบริษัทเดียวกันที่ไม่ได้อยู่ในห้องก็เปิดไฟล์ห้องนั้นได้
ถ้าได้ลิงก์ตรง — ขัดกับข้อสัญญา "แต่ละบริษัทเห็นแค่ของตัวเอง / เจ้าของคุมว่าใครเห็นอะไร"

**แก้ 2 ชั้น:**
- ชั้นบริษัท — key ต้องขึ้นต้นด้วย orgId ของ session ตัวเอง ไม่งั้น 403
- ชั้นห้อง — ไฟล์คลังกลาง (company-files) ที่อยู่ในโฟลเดอร์ผูกห้อง ต้องเป็นสมาชิกห้องนั้นถึงโหลดได้

**และ:** แก้โมดูล maintenance ที่เดิมเก็บไฟล์โดยไม่มี orgId นำหน้า ให้ใส่ครบทั้ง 7 จุด
(รูปอุปกรณ์ / ใบเสร็จ / PO×2 / รูปงานซ่อม / รูปหลังซ่อม / คอมเมนต์ / แจ้งคืนของ)

**ไฟล์:**
- แก้ `app/api/files/[...key]/route.ts` — บังคับ orgId + เรียกเช็คสิทธิ์ห้อง
- ใหม่ `modules/company-files/lib/serve-access.ts` — เช็คสิทธิ์ห้องตอนเสิร์ฟไบต์
- แก้ `app/(shell)/maintenance/{assets,expenses,purchase-orders,work-orders}/actions.ts`

**ค้างไว้ (ตามที่สั่ง — ไม่แตะข้อมูลเสี่ยง):** ไฟล์ maintenance ที่อัปก่อนแก้ยังไม่มี orgId
ใส่ grandfather ชั่วคราวให้ของเดิมไม่พัง (ยังเปิดข้ามบริษัทด้วย URL ได้อยู่จุดเดียว) —
ถ้าจะปิดสนิทต้องทำ migration ย้าย key เก่า หรือล้าง test แล้วลบ grandfather

## 3. ระบบเพดานความจุต่อบริษัท (แพ็กเกจเสริม)

**เป้าหมาย:** ผู้ขายคุมได้ว่าบริษัทไหนใช้พื้นที่ไฟล์ได้เท่าไร ขายเป็นแพ็กเกจเสริม + กันค่า storage วิ่งหนี

**ทำแล้ว:**
- นับพื้นที่ที่ใช้จริงต่อบริษัท (ไฟล์คลังกลาง) + เพดาน + บล็อกอัปโหลดเมื่อเต็ม (พร้อมข้อความให้อัปเกรด)
- เพดานตั้งได้ **2 ระดับ**: ค่ากลางจาก env `COMPANY_FILES_ORG_QUOTA_GB` (ดีฟอลต์ 5GB)
  และ **เพดานเฉพาะบริษัท** ตั้งจากหน้าหลังบ้าน (ถ้าตั้งไว้ ใช้ค่านี้แทนค่ากลาง)
- เมนูหลังบ้านใหม่ **"พื้นที่จัดเก็บไฟล์ (ทุกบริษัท)"** → `/admin/storage` เห็นเฉพาะ super-admin
  แสดงการใช้พื้นที่ทุกบริษัท + แถบสี + ป้าย ปกติ/ใกล้เต็ม/เต็มแล้ว + ช่องกรอก GB ตั้งเพดานรายบริษัท

**ไฟล์:**
- ใหม่ `modules/company-files/lib/quota.ts` — usage/limit/check
- แก้ `app/api/company-files/uploads/route.ts` — เช็ค quota ก่อนเก็บไฟล์
- ใหม่ `app/(shell)/admin/storage/page.tsx` + `actions.ts`
- แก้ `modules/admin/manifest.ts` (เมนู) + `lib/icons.ts` (ไอคอน HardDrive) + `modules/admin/data/orgs.ts` (คืน storageQuotaMb)
- schema: `packages/database/prisma/schema/core.prisma` เพิ่ม `storageQuotaMb Int?`
- migration: `packages/database/prisma/schema/migrations/20260901120000_add_org_storage_quota/`

**ขอบเขตปัจจุบัน:** นับเฉพาะไฟล์คลังกลาง (company-files) ยังไม่รวมแชท/รายงาน/งานซ่อม

## ต้องทำก่อน deploy

1. **มีการแก้ schema (เรื่อง 3)** — ต้องรัน migration + regenerate prisma client ก่อน:
   - dev: `pnpm db:migrate`
   - prod: `pnpm db:deploy` แล้ว `pnpm db:generate`
2. รัน `pnpm typecheck` และ build ในเครื่อง dev จริง
   (บนเครื่องที่แก้ typecheck เต็มไม่ได้ เพราะ dependency ถูก pnpm hoist)
3. ไฟล์สำรองที่ถูกแทนที่ ย้ายไปที่ `apps/web/_to_delete/` — ลบทิ้งได้

## สคริปต์สาธิต (สำหรับนำเสนอ เรื่อง 3)

หลังบ้าน → "พื้นที่จัดเก็บไฟล์ (ทุกบริษัท)" → เห็นทุกบริษัทใช้พื้นที่เท่าไร →
กรอก GB ให้บริษัทหนึ่งแล้วบันทึก (แถบ/เพดานเปลี่ยนทันที) →
อัปไฟล์จนเกินเพดาน → ระบบบล็อกพร้อมข้อความให้อัปเกรด = เล่าเป็น "แพ็กเกจเสริมความจุ"
