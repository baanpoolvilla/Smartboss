# ห้องแชท "คำขออนุมัติ" — อนุมัติขอเลื่อนจากแชท

วันที่ 18/11/2569 · ภาพตัวอย่าง: https://claude.ai/artifact/NrbyxUkyWP61xnPAB2psAG

## ทำไม
ทุกวันนี้ถ้าจะดูคำขอเลื่อน ต้องเปิดหน้าบอร์ดหรือหน้าใบงาน ผู้ใช้อยากให้คำขอมาเด้งในแชทระบบแบบห้อง "ระบบลงเวลา"
จะได้กันลืม และกดอนุมัติในแชทได้เลย ใช้กับทั้ง 2 โมดูล คืองาน/Task และใบแจ้งซ่อม

## เป้าหมาย
- ห้องระบบใหม่ต่อคน ชื่อ "คำขออนุมัติ" (id คงที่ เช่น `approve-<userId>` แบบห้อง `clock-<userId>`) ห้องขึ้นเมื่อมีคำขอแรก
- คำขอ 3 แบบเข้าห้องนี้ เป็นการ์ดที่มีปุ่ม อนุมัติ / ไม่อนุมัติ / ดูรายละเอียด
  1. ขอเลื่อนกำหนดส่งงาน/Task — คนอนุมัติตามกติกาเดิม: คนมอบหมาย · งานโปรเจกต์ที่มอบให้ตัวเองไปหาผู้ดูแลโปรเจกต์ · ผู้ดูแลมอบให้ตัวเองไปหา Boss (ตรงกับ approverIds ใน `requestDueDateChange`)
  2. ขอเลื่อนกำหนดส่งใบแจ้งซ่อม — คนอนุมัติ = คนเปิดใบงาน · ถ้าคนเปิดเป็นคนขอเอง (หรือไม่มีคนเปิด) ไปหาคนเดียวกับที่ได้กระดิ่ง "รออนุมัติ" ในปัจจุบัน
  3. ขอเลื่อนกำหนดบันทึกค่าใช้จ่ายของใบแจ้งซ่อม (`kind = "expense"`) — Boss ตามเดิม · หัวการ์ดเขียนว่า "ขอเลื่อนบันทึกค่าใช้จ่าย"
- สรุปคือการ์ดเข้าห้องของคนเดียวกับคนที่ได้กระดิ่งเรื่องนั้นในปัจจุบัน
- บนการ์ดมี: ประเภท (Task / ใบแจ้งซ่อม) รหัส ป้าย (PM ฯลฯ) ชื่องาน คนขอ ขอให้ใครบ้าง (ถ้าเป็นงานกลุ่ม) วันเดิม → วันใหม่ เลื่อนกี่วัน เหตุผล
- กดอนุมัติในแชท = เรียกคำสั่งอนุมัติตัวเดิม ผลจึงเหมือนกดที่บอร์ดหรือหน้าใบงานทุกอย่าง: เปลี่ยนวัน คอมเมนต์ ✅/❌ แจ้งคนขอ การ์ดแดงบนบอร์ดหาย กระดิ่งเคลียร์
- การ์ดเปลี่ยนตามสถานะจริงเสมอ: รออนุมัติ → อนุมัติแล้ว / ไม่อนุมัติ (ชื่อคนกด + เวลา) / ยกเลิกแล้ว ไม่ว่าจะกดจากที่ไหน
- งานกลุ่ม: ปุ่ม "อนุมัติทั้ง N คน" = เลื่อนให้ตามที่ขอมา · ถ้าจะเลือกเอง กด "เลือกบางคน" พาไปหน้างานหรือหน้าใบงาน
- การแจ้ง: แชทขึ้นแค่ตัวเลขยังไม่อ่าน ไม่เด้ง ไม่ส่ง push หรือ LINE ซ้ำ · กระดิ่งยังทำงานเหมือนเดิม
- ไม่อนุมัติ: เปิดแผ่นใส่หมายเหตุ · งานไม่บังคับใส่หมายเหตุ (ตามเดิม) · ใบแจ้งซ่อมบังคับใส่เหตุผล (ตามเดิม)

## ไม่ทำ (ตอนนี้)
- "เคยเลื่อนมาแล้วกี่ครั้ง / กำหนดแรก" และ "ขอตอนเลยกำหนดแล้ว X วัน" — ผู้ใช้สั่งพักไว้ก่อน
- ไม่ย้ายคำขออนุมัติอื่นเข้าห้องนี้ เช่น OT เบิกจ่าย ขอแก้คะแนน
- ไม่เปลี่ยนกระดิ่ง และไม่เปลี่ยนกติกาว่าใครอนุมัติได้

## ห้ามพลาด
- ห้ามมีทางอนุมัติทางที่สอง ปุ่มในแชทต้องใช้ตัวเดียวกับของเดิม
- การ์ดค้างสถานะ "รออนุมัติ" ทั้งที่ตัดสินไปแล้ว ถือว่าพลาด
- คนที่ไม่มีสิทธิ์อนุมัติต้องไม่เห็นการ์ด และกดไม่ได้ ระบบต้องเช็กสิทธิ์ซ้ำตอนกดด้วย
- การ์ดพลาดต้องไม่ทำให้การขอเลื่อนพลาด (ไม่ throw แบบ `postTaskCard`)

## แนวทาง
- **เลือก:** การ์ดในห้องระบบ + ปุ่มเรียกคำสั่งอนุมัติเดิม
  - งาน/Task: ตัดสินที่ฝั่งเครื่องผ่าน `useTaskStore.decideDueDateRequest` (ต้องโหลดงานในหน้าแชทก่อนกด)
  - ใบแจ้งซ่อม: ใช้ `decideDueRequestAction` และ `decideExpenseExtensionAction`
- **ไม่เลือก:** เขียนตัวอนุมัติงานใหม่ฝั่ง server — งานบันทึกจากฝั่งเครื่อง ถ้าเขียนจากสองฝั่งจะชนกัน (มีบทเรียนจาก due-request-race / task save timeout) และกลายเป็นสองทางที่ทำงานต่างกัน
- **ไม่เลือก:** โพสต์ลงแชทส่วนตัวระหว่างคนขอกับคนอนุมัติ — ผู้ใช้อยากได้แชทของระบบแบบห้องลงเวลา

## ปล่อยให้คนทำตัดสินเอง
- สถานะบนการ์ด: อ่านสดจากคำขอจริงตอนแสดง หรืออัปเดตข้อความ meta แล้ว broadcast
- ชื่อ prefix ของห้อง และรูปไอคอนปฏิทิน
- ห้องนี้ตั้งชื่อไม่ได้ ออกไม่ได้ ตอบกลับไม่ได้ เหมือนห้องระบบลงเวลา
